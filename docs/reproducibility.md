# Reproduction

Experiment definitions, seeds, and dataset checksums are in
`configs/release.yaml`.

## Check results or rerun experiments

```bash
python scripts/verify_paper_results.py
python scripts/reproduce_release.py --dry-run
python scripts/reproduce_release.py --preflight
python scripts/reproduce_release.py --suite main --execute
```

The statistics check covers Tables 2, 3, 4, 11, 14, 15, and 16. References are
in `figure_specs/paper_results.yaml`; the command recomputes statistics from
per-seed records and checks seed sets, parameter counts, and hash fields.

Omit `--suite main` to run all suites; repeat `--suite` to select several.
Use `--stage data`, `train`, `evaluate`, `reports`, or `figures` for one stage.
Dependencies are selected automatically; matching completed runs are reused.
Use a new output directory for a fresh run. Report commands write CSV/TeX files.

## Data and checkpoints

The workflow generates the Galilean N64, unboosted N64, Burgers N128, and
Dirichlet heat datasets before training. To generate only data, run:

```bash
python scripts/reproduce_release.py --stage data --execute
```

Reference dataset checksums are recorded in `configs/release.yaml`.
Checkpoint evaluation checks the dataset checksum saved with the model.

The rMD17 reference split is included in `data/rmd17/rmd17_ethanol_force_500.pt`.
Use this tensor to evaluate the same samples; its recorded `old_indices`
define the split. `scripts/verify_rmd17_cached_dataset.py` checks the tensor
against the raw NPZ using those indices and the raw-data hash.

Evaluate a checkpoint with its saved seed and orbit settings:

```bash
python scripts/evaluate.py --checkpoint PATH/checkpoints/best.pt --device cpu --out evaluation.json
```

Use `--dataset PATH` to relocate data; its saved SHA-256 must match. Model
checkpoints are generated by training and are not stored in Git. Report and
checkpoint-dependent figure stages run after training. Measure latency on the
target machine.

## Training and checkpoint records

Runs save the resolved config and hash, dataset SHA-256, source hashes,
environment, metrics, and RNG snapshots. `best.pt` is selected by validation
error; `last.pt` contains the final model and matching optimizer state.
The workflow sets OMP and MKL threads to one. Dependencies are pinned in
`uv.lock`; each run records its execution environment in `meta.json`.

Seeded retraining supports statistical comparisons. Use saved checkpoints
when a comparison requires identical model weights. Resuming training also
requires the saved optimizer and RNG state. Compare training times using
complete-run measurements.
